> **读者**：`jingcaiMarket` 小程序前台（Cursor 可直接 `@` 本文件联调）。  
> **维护**：Java 后台 `PlatformCustomerController` 及关联 Service。

> **Controller 前缀**：`api/platform/customer`  
> **业务主权**：`docs/nxPlatform/platform-cart-checkout-bill-design.md`（已定稿）。本文件描述**当前 HTTP 路径、字段与前端联调语义**。

## 1. 第一轮重构后的核心语义（必读）

| # | 规则 | 前端理解 |
|---|------|----------|
| 1 | **`submitBySupplier` 已降级** | 仅「已选配送商商品 **写入购物车**」；**不生成 bill**、不 assign、不进入配送商/Electric 可见域 |
| 2 | **`submitLine` 已降级** | 仅「未选配送商商品 **写入购物车**」；**只写 NX 临时行**；**不进入 Electric**、不 assign |
| 3 | **购物车列表** | 只展示 `nx_DO_status = -1` 的临时行；用 **`POST .../cart/lines/list`** |
| 4 | **`checkoutPreview`** | 对本批购物车行分组：**已知价 / 未知价**；返回本次应付 **`knownTotal`**（= `payAmount`） |
| 5 | **`checkoutConfirm`** | **本地 mock**：跳过微信支付，直接创建 bill 并正式化（`paidTotal=knownTotal`） |
| 5b | **`checkoutPay`** | **生产主链**：创建 PENDING 支付 + 微信 JSAPI；**支付成功回调后**才创建 bill / 正式 order |
| 6 | **Checkout 前不可见** | 配送商端、Electron 分配台 **都看不到** 购物车临时行（`status=-1`） |
| 7 | **Bill 封口** | Checkout 后 bill 内商品集合 **固定**；**禁止**往旧 bill 追加新商品；新加购 → 新 checkout → **新 bill** |
| 8 | **补款** | 只针对 bill 内 **checkout 时已存在的 PENDING 价格行** 称重/改价后的差额；用 `paySupplement`，**不是**追加商品 |

### 1.1 两个维度不要混

| 维度 | 字段 | 含义 | 何时有意义 |
|------|------|------|------------|
| **价格** | `priceConfirmStatus` | `CONFIRMED` 已知价 / `PENDING` 待确认价 | 购物车起即可算；影响 `knownTotal` |
| **配送商** | `assignStatus` | `ASSIGNED` 已选或已分配 / `PENDING` 待平台分配 | **仅 `checkoutConfirm` 之后**才有 assign 记录 |

`pendingPriceItemCount` = **价格未知**行数，**不是**「待分配配送商」行数。

### 1.2 前端推荐页面流

```
商品页（已选批发商） ──submitBySupplier──► 购物车临时行 status=-1
全部类别选品         ──submitLine────────► 购物车临时行 status=-1（仅 NX）

购物车 Tab ──cart/lines/list──► 展示全部 status=-1 行
         ──勾选/全选────────► orderIds[]

结算页 ──checkoutPreview(orderIds)──► 已知价合计 knownTotal + 分组展示
       ──checkoutPay(orderIds, checkoutToken, openId)──► wxPayParams（生产）
       ──checkoutConfirm(orderIds, checkoutToken)──► billId（本地 mock 联调）
       ──wx.requestPayment(wxPayParams)──► 支付成功回调后才生成 bill

已 checkout 订单 ──orders/listTodayLines──► 正式单（有 assign）；**不是**购物车数据源
```

## 2. 接口一览

| 用途 | 方法 | 路径 | 阶段 |
|------|------|------|------|
| 购物车列表（**主数据**） | POST | `api/platform/customer/cart/lines/list` | Checkout 前 |
| 修改购物车行 | POST | `api/platform/customer/cart/lines/update` | Checkout 前 |
| 删除购物车行 | POST | `api/platform/customer/cart/lines/delete` | Checkout 前 |
| 已选配送商 · 加购 | POST | `api/platform/customer/cart/submitBySupplier` | Checkout 前 |
| 未选配送商 · 加购 | POST | `api/platform/customer/orders/submitLine` | Checkout 前 |
| 结算预览 | POST | `api/platform/customer/cart/checkout/preview` | Checkout |
| 结算确认（**本地 mock**） | POST | `api/platform/customer/cart/checkout/confirm` | Checkout 联调 |
| 结算支付（**生产主链**） | POST | `api/platform/customer/cart/checkout/pay` | Checkout |
| 支付状态查询 | POST | `api/platform/customer/cart/checkout/payment/status` | Checkout 支付后 |
| 取消支付 | POST | `api/platform/customer/cart/checkout/payment/cancel` | 用户取消微信支付 |
| 微信支付回调 | POST | `api/platform/customer/cart/checkout/payment/notify/wechat` | 微信服务器 |
| 今日正式订货（checkout 后） | POST | `api/platform/customer/orders/listTodayLines` | Checkout 后 |
| 修改/删除（**仅 checkout 后 PENDING assign**） | POST | `.../orders/updateLine` · `deleteLine` | Checkout 后 |
| 首页待支付 | POST | `api/platform/customer/home/init` | 任意 |
| 首次支付 | POST | `api/platform/customer/bill/payFirst` | Checkout 后 |
| 补款支付 | POST | `api/platform/customer/bill/paySupplement` | Checkout 后 |

统一响应：`R` 对象，`code === 0` 成功。

| code | 含义 |
|------|------|
| `0` | 成功 |
| `4001` | 有待支付 bill，阻塞 `checkoutConfirm`（与旧 `submitBySupplier` 阻塞逻辑一致） |
| `4002` | 参数或业务校验失败 |
| 其他 | 一般错误，`msg` 为说明 |

#### 3.2.1 行字段 `PlatformCartLineItem`

| 字段 | 类型 | 说明 |
|------|------|------|
| `nxOrderId` | Integer | NX 购物车行 ID（勾选、改删、checkout 用） |
| `gbOrderId` | Integer | GB 临时行 ID；未选批发商加购时为 `null` |
| `nxGoodsId` | Integer | 标准商品 ID |
| `nxDistributerId` | Integer | 关联批发商/配送商 ID（待分配行也可能有占位值） |
| `nxDistributerGoodsId` | Integer | 批发商 SKU；**有值表示已选批发商加购** |
| `goodsName` | String | 商品名 |
| `goodsImage` | String | 商品缩略图（相对路径，拼 CDN/域名与现有商品图一致） |
| `goodsImageLarge` | String | 大图，可选 |
| `quantity` | String | 订货数量 |
| `standard` | String | 订货单位 |
| `priceConfirmStatus` | String | `CONFIRMED` 已知价 / `PENDING` 待确认价 |
| `unitPrice` | String | 已知价时单价（如 `1.3`）；前端展示「单价：¥1.30/斤」 |
| `pricingStandard` | String | 单价对应单位（如 `斤`），与 `unitPrice` 组合 |
| `lineSubtotal` | String | 行小计；`PENDING` 时为 `null` |
| `remark` | String | 备注 |
| `hasSupplierSelected` | Boolean | 是否已选批发商加购（对应 UI「已选批发商」标签） |
| `editable` | Boolean | 是否可改删；**PENDING 支付锁定期间为 `false`** |
| `paymentLocked` | Boolean | 本行处于 checkout 支付 PENDING 锁定 |
| `paymentProcessing` | Boolean | 同 `paymentLocked`，用于展示「支付处理中」 |
| `paymentProcessingMessage` | String | 锁定时为 `"支付处理中"`，否则 `null` |
| `supplier` | Object | 已选批发商卡片；未选时为 `null` |

**`supplier`（`PlatformCartSupplierItem`）**

| 字段 | 说明 |
|------|------|
| `nxDistributerId` | 批发商 ID |
| `supplierName` | 展示名（优先 `nx_distributer_show_name`） |
| `supplierLogo` | Logo/头像（`nx_distributer_img`） |
| `supplierAddress` | 地址 |
| `supplierPhone` | 联系电话 |

**前端分组建议**（无需后台再拆接口）：

- `priceConfirmStatus === 'CONFIRMED'` → 「已知价格商品」
- `priceConfirmStatus === 'PENDING'` → 「未知价格商品」
- `hasSupplierSelected === true` → 展示「已选批发商」标签 + `supplier` 卡片
- `hasSupplierSelected === false` → 展示「待分配批发商」类提示（checkout 前无 assign）

`checkoutPreview` / `checkoutConfirm` 返回的 `PlatformCheckoutLineItem` **包含与上表相同的展示字段**，另加 `assignStatus`（预览时为 `null`）。

**筛选规则（后台保证）**：仅 `nx_DO_status = -1`（购物车临时阶段）。  
Checkout 后的正式行 **不会** 出现在本接口。

| 行类型 | `gbOrderId` | `nxDistributerGoodsId` | 说明 |
|--------|-------------|--------------------------|------|
| 已选配送商加购 | 有 | 有 | 同时有 GB+NX 临时行 |
| 未选配送商加购 | `null` | `null` | 仅 NX 临时行；GB 在 `checkoutConfirm` 才创建 |

**Checkout 前数据约束**（联调/断言用）：

- `nx_DO_status = -1`
- 已选配送商行：`gb_DO_status = -1`，且 **`gb_DO_bill_id` 必须为 `null`**
- **无** `nx_platform_order_assign` 记录

### 3.3 修改购物车行

`POST api/platform/customer/cart/lines/update`

**仅** `status=-1` 且 `gb_DO_bill_id IS NULL` 的临时行可改；已 checkout / 已挂 bill 返回 `4002`。

```json
{
  "marketId": 1,
  "gbDepartmentId": 58,
  "nxOrderId": 200214,
  "quantity": "5",
  "standard": "斤",
  "remark": ""
}
```

成功 `data`：更新后的 `PlatformCartLineItem`（含重算后的 `priceConfirmStatus`、`lineSubtotal`）。

**后台行为**：

- 校验 `gbDepartmentId` 归属、`nx_DO_status=-1`、无 assign、无 bill
- 已选配送商行：同步更新 GB+NX，并重算 `priceConfirmStatus` / 小计
- 未选配送商行：仅更新 NX；价格仍为 `PENDING`
- **不**触发 assign / fulfillment / 配送商通知

### 3.4 删除购物车行

`POST api/platform/customer/cart/lines/delete`

```json
{
  "marketId": 1,
  "gbDepartmentId": 58,
  "nxOrderId": 200214
}
```

成功：`code=0`，无 `data`。删除后 `cart/lines/list` 不再返回该行；**不影响**已生成 bill。

**后台行为**：删除关联 GB 临时行（若有）+ NX 行；不触发 assign / fulfillment。

**前端建议**：删除或修改成功后重新调用 `cart/lines/list` 与 `checkoutPreview(selectedIds)` 刷新列表与底部合计。

## 4. 已选配送商 · 加购

`POST api/platform/customer/cart/submitBySupplier`

**语义**：客户在某批发商商品页点「确定」→ **写入购物车**，不是即时下单。

```json
{
  "marketId": 1,
  "gbDepartmentId": 58,
  "gbDepartmentFatherId": 57,
  "gbDistributerId": 12,
  "nxDistributerId": 56,
  "gbOrderUserId": 18,
  "deliveryDate": "2026-06-20",
  "remark": "",
  "items": [
    {
      "nxDistributerGoodsId": 22151,
      "nxGoodsId": 101837,
      "goodsName": "绿甘蓝",
      "quantity": "3",
      "standard": "斤"
    }
  ]
}
```

成功 `data`：`PlatformCartAddWithSupplierResponse`

| 字段 | 说明 |
|------|------|
| `nxDistributerId` | 本次选中的批发商 |
| `supplierName` | 批发商名称 |
| `addedLineCount` | 新增行数 |
| `lines[]` | `PlatformCartLineItem`：`nxOrderId`、`gbOrderId`、`priceConfirmStatus`、`lineSubtotal` 等 |

**不再返回**（旧版已废弃）：`billId`、`billPayState`、`knownPayAmount`、`payableNow`。

**后台行为**：

1. 写 GB + NX 临时行（`status=-1`）
2. **`gb_DO_bill_id = null`**
3. **不**创建 assign / fulfillment
4. **不**创建 bill
5. 配送商端、Electron **不可见**

## 5. 未选配送商 · 加购

`POST api/platform/customer/orders/submitLine`

**语义**：全部类别选品 → **写入购物车**（来源 A）；**不进入 Electric**。

```json
{
  "marketId": 1,
  "departmentId": 58,
  "nxGoodsId": 100088,
  "goodsName": "大土豆",
  "quantity": "1",
  "standard": "个",
  "remark": "",
  "orderUserId": 18
}
```

成功 `data`：`PlatformSubmitLineResponse`

| 字段 | 说明 |
|------|------|
| `orderId` | 新建 NX 订单 ID（购物车行 ID） |
| `nxGoodsId` / `goodsName` / `quantity` / `standard` | 商品信息 |
| `priceConfirmStatus` | 一般为 `PENDING` |
| `lineSubtotal` | 未知价时为 `null` |

**不再返回**（旧版已废弃）：`platformAssignId`、`assignStatus`、`assignMode`。

**后台行为**：

1. 仅写 NX 临时行（`status=-1`）
2. **不**写 GB 行（checkoutConfirm 时补建）
3. **不**创建 assign → Electric **不会**收到待分配单

## 6. 结算预览

`POST api/platform/customer/cart/checkout/preview`

```json
{
  "marketId": 1,
  "gbDepartmentId": 58,
  "orderIds": [200214, 200215]
}
```

| 字段 | 说明 |
|------|------|
| `orderIds` | 本批待结算的 NX 订单 ID；必须均为购物车 `status=-1` |

成功 `data`：`PlatformCheckoutPreviewResponse`

| 字段 | 说明 |
|------|------|
| `confirmedLines[]` | 已知价行（`priceConfirmStatus=CONFIRMED`） |
| `pendingPriceLines[]` | 未知价行（`priceConfirmStatus=PENDING`） |
| `confirmedItemCount` | 已知价行数 |
| `pendingPriceItemCount` | **价格**待确认行数（≠ assign 待分配） |
| `knownTotal` | 已知价小计合计，两位小数 |
| `payAmount` | **本次应付 = knownTotal**（未知价不计入） |
| `notice` | 固定提示：部分商品需称重，完成后可能补款 |

预览阶段 **不** 写库、**不** 创建 bill、**不** 创建 assign。  
`PlatformCheckoutLineItem.assignStatus` 在预览时为 **`null`**。

## 7. 结算确认（本地 mock）

> **生产环境请走 §7b `checkoutPay`**。`checkoutConfirm` 保留用于本地联调：跳过微信支付，直接 mock「已支付」并生成 bill。

`POST api/platform/customer/cart/checkout/confirm`

```json
{
  "marketId": 1,
  "gbDepartmentId": 58,
  "gbDepartmentFatherId": 57,
  "gbDistributerId": 12,
  "gbOrderUserId": 18,
  "deliveryDate": "2026-06-20",
  "remark": "",
  "orderIds": [200214, 200215],
  "checkoutToken": "checkout-uuid-xxx"
}
```

| 字段 | 说明 |
|------|------|
| `checkoutToken` | 本批 checkout 幂等 token；**每次确认用新 UUID** |
| `orderIds` | 与 preview 一致的本批购物车行 |

成功 `data`：`PlatformCheckoutConfirmResponse`

| 字段 | 说明 |
|------|------|
| `billId` | **新建** GB 采购单 ID |
| `billTradeNo` | 平台 bill 流水号 |
| `knownTotal` | 已知价合计 |
| `paidTotal` | mock 路径下 = `knownTotal`（视为已付已知价部分） |
| `pendingPriceItemCount` | bill 内价格待确认行数 |
| `supplementDue` | 待补款（confirm 后一般为 0） |
| `payStatus` | 如 `PARTIAL_PAID` / `PAID` |
| `lines[]` | 本批行；含 `assignStatus`：`ASSIGNED` 或 `PENDING` |
| `idempotent` | 重复 token 时为 `true` |

**后台行为（一次性）**：

1. **新建** `gb_department_bill`（不是往旧 bill 追加）
2. 本批全部 NX 行转正式（`nx_DO_status: -1 → 0`）
3. 已选配送商行：GB 行转正式并 **`gb_DO_bill_id = billId`**
4. 未选配送商行：**新建** GB stub 并 **`gb_DO_bill_id = billId`**
5. 创建 assign：已选配送商 → `ASSIGNED`；未选 → `PENDING`（Electric 可见起点）
6. 已选配送商且需 dep_dis / purchase 的行：checkout 时补转正

**Checkout 后数据约束**：

- 本批所有 GB 行：**`gb_DO_bill_id` 必须等于本次 `billId`**
- 配送商端：仅 **checkout 后且 `assignStatus=ASSIGNED`** 的行可见
- Electron：仅 **checkout 后** 的 assign 进入待办（`PENDING` / `ASSIGNED`）

常见失败：

| code | 场景 |
|------|------|
| `4001` | 存在未结清 outstanding bill |
| `4002` | orderIds 含非购物车行、不属于当前门店等 |

## 7b. 结算支付（生产主链）

`POST api/platform/customer/cart/checkout/pay`

入参与 `checkoutConfirm` 相同，**额外必填** `openId`（小程序用户 openId）。

```json
{
  "marketId": 1,
  "gbDepartmentId": 58,
  "gbDepartmentFatherId": 57,
  "gbDistributerId": 12,
  "gbOrderUserId": 18,
  "deliveryDate": "2026-06-20",
  "remark": "",
  "orderIds": [200214, 200215],
  "checkoutToken": "checkout-uuid-xxx",
  "openId": "oXXXX"
}
```

| 校验 | 说明 |
|------|------|
| 购物车行 | 全部 `status=-1`，与 preview 同批 `orderIds` |
| `knownTotal` | 与 preview 同口径重算，**必须 > 0** |
| 4001 | 存在未结清 outstanding bill 时阻断 |

成功 `data`：`PlatformCheckoutPayResponse`

| 字段 | 说明 |
|------|------|
| `paymentId` | checkout 支付意图 ID（`platform_checkout_payment`） |
| `knownTotal` / `payAmount` | 本次微信支付金额 |
| `outTradeNo` | 微信商户订单号 |
| `wxPayParams` | 小程序 `wx.requestPayment` 参数（`appId/timeStamp/nonceStr/package/signType/paySign`） |
| `mockPay` | 恒为 `false` |
| `billId` | 仅支付已成功（幂等重入）时有值 |

**支付成功前**：

- **不**创建 `gb_department_bill`
- order 仍为购物车 `status=-1`
- 配送商 / Electric **不可见**

**微信支付成功回调后**（`.../payment/notify/wechat`）才执行与 `checkoutConfirm` 相同的正式化：

1. 新建 bill 并挂全批行
2. `status: -1 → 正式`
3. `paidTotal = knownTotal`
4. 有配送商 → `assignStatus = ASSIGNED`；无 → `PENDING`

**支付失败 / 用户取消**：不生成 bill；购物车行不变；无 assign。

**幂等**：相同 `checkoutToken` 重复调用返回同一 PENDING 支付（重签 `wxPayParams`）或已 SUCCESS 的 bill 摘要。

**PENDING 期间锁定**（本批 `orderIds` 快照，**仅未超时的 PENDING**）：

- 禁止 `cart/lines/update`、`cart/lines/delete`
- 禁止再次 `checkoutPreview` / `checkoutPay` / `checkoutConfirm`（含 overlapping orderIds）
- 购物车 **仍展示** 被锁行，但 `editable=false`、`paymentProcessing=true`
- 释放方式：
  - 前端取消：`POST .../payment/cancel`
  - 超时：`payment/status` 或 `checkoutPay` 前自动 `EXPIRED`（默认 15 分钟，可配置）
  - 后续可加定时任务清理超时 PENDING

**payment 状态**：`PENDING` / `SUCCESS` / `FAILED` / `CANCELLED`（用户取消）/ `EXPIRED`（超时）

**payment 快照字段**（`platform_checkout_payment`）：`orderIds`、`knownTotal`、`pendingPriceItemCount`、`gbDepartmentId`、`checkoutToken`、`outTradeNo`、`expireAt`；成功后写入 `billId`、`transactionId`、`paidAt`、`notifyRaw`。

**微信回调安全（API v2 MD5）**：验签、`appid`/`mch_id`/`out_trade_no`/`total_fee`（分）/`result_code` 校验；**非** API v3 解密回调。

## 7c. 支付状态查询

`POST api/platform/customer/cart/checkout/payment/status`

```json
{
  "paymentId": 1001,
  "gbDepartmentId": 58
}
```

`paymentId` / `outTradeNo` / `checkoutToken` 三选一；建议带 `gbDepartmentId` 校验归属。

成功 `data`：`PlatformCheckoutPaymentStatusResponse`

| 字段 | 说明 |
|------|------|
| `status` | `PENDING` / `SUCCESS` / `FAILED` / `CANCELLED` / `EXPIRED` |
| `locked` | 是否仍锁定购物车（`PENDING` 且未超时） |
| `expired` | 是否已超时关闭（`EXPIRED`） |
| `billId` | 仅 `SUCCESS` 且 finalize 完成时有值 |
| `billPayStatus` | bill 的 `payStatus`（如 `PARTIAL_PAID`） |
| `knownTotal` | 快照金额 |
| `pendingPriceItemCount` | 快照未知价行数 |
| `orderIds` | 快照 nxOrderId 列表 |
| `transactionId` / `paidAt` | 支付成功后有值 |
| `message` | 前端提示文案 |

前端在 `wx.requestPayment` success 回调后轮询本接口，直到 `status=SUCCESS` 且 `billId` 非空。  
用户取消支付后调用 `payment/cancel`，或轮询到 `CANCELLED`/`EXPIRED`/`FAILED` 后允许重新 checkout。

## 7d. 取消支付

`POST api/platform/customer/cart/checkout/payment/cancel`

```json
{
  "paymentId": 1001,
  "gbDepartmentId": 58
}
```

`paymentId` / `outTradeNo` 二选一；必须带 `gbDepartmentId` 校验归属。

规则：

- 仅可取消 **自己的、仍为 PENDING 且未超时** 的 payment
- `SUCCESS` 不可取消
- 取消后 `status=CANCELLED`，不生成 bill，order 保持 `status=-1`
- 购物车行恢复可改删、可重新 checkout

## 8. Checkout 后的正式订货列表

`POST api/platform/customer/orders/listTodayLines`

**用途**：展示 **已 checkout** 的正式订货（有 assign），**不是**购物车 Tab 数据源。

```json
{
  "marketId": 1,
  "departmentId": 58,
  "applyDate": "2026-06-21"
}
```

行字段见 `PlatformCustomerOrderLineItem`（含 `assignStatus`、`statusCode`、`editable` 等）。  
购物车临时行（`status=-1`）**不会**出现在此列表。

`editable === true`：仅 checkout 后 **`assignStatus=PENDING`** 且未分配配送商的行，可走 `updateLine` / `deleteLine`。

## 9. Bill 与支付

### 9.1 Bill 生命周期

| 时机 | bill |
|------|------|
| 加购 / 购物车 | **无 bill** |
| `checkoutConfirm` | **新建一张 bill**，挂本批全部行 |
| 后续新加购 | 必须再次 checkout → **新 bill**；**禁止**追加到旧 bill |
| 补款 | 同一张 bill；仅 PENDING 价格行称重后 `supplementDue > 0` |

### 9.2 支付接口（桩联调）

| 接口 | 用途 |
|------|------|
| `POST .../bill/payFirst` | 首次支付 `knownTotal` 对应部分 |
| `POST .../bill/paySupplement` | bill 内原有 PENDING 行称重后的差额 |

`POST .../home/init`：`hasOutstandingBill` / `outstandingBill` 与 checkout 阻塞逻辑一致。

> **本轮不做**：真实微信支付、回调、司机路线、配送商结算。
