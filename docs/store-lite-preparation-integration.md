# 门店中间料小程序接入边界

## 当前能力

当前门店中间料只是菜品配方中的标准加工组成。小程序只提供：

- 新增、编辑、启用和停用中间料；
- 维护标准产出和一层原料配比；
- 菜品配方中选择中间料并填写每份用量；
- 展示菜品通过中间料展开后的底层原料。

当前页面不提供中间料制作、库存、生产批次、损耗或废弃新增入口。旧 `storeLoss` 路由保留兼容但只显示能力停用说明，不再加载表单或调用写入接口；`storeLossRecords` 只用于查询既有历史记录，并且仅在中间料确有旧记录时从详情页显示入口。

## 版本和成本链

菜品新版配方发布时，后端必须把当时采用的具体中间料版本写入 `intermediateRecipeVersionId`。页面只展示后端返回的版本与展开结果，不得根据中间料名称、`versionNo` 或当前发布指针推测历史内容。

```text
营业日期
→ effectiveInterval
→ 菜品 contentVersionId
→ intermediateRecipeVersionId
→ 中间料组件
→ 底层采购原料
→ 历史理论成本
```

中间料展开量为“菜品每份中间料基础用量 × 中间料原料基础用量 ÷ 中间料标准产出基础用量”。中间料没有独立库存价、制作价或参考成本入口。

## 当前不实现

- 中间料库存和半成品库存；
- 中间料制作或生产记录；
- 中间料生产批次；
- 中间料单独损耗或废弃；
- 按中间料数量展开原料损耗；
- 中央厨房生产流程。

相关旧表和旧接口继续保留以保护历史数据及兼容旧调用，但不能作为当前功能入口或当前成本数据源。小程序不得再引导用户新增中间料损耗或废弃记录。

## 后续扩展

如未来建设中央厨房或半成品库存，需重新设计生产批次、实际投料、实际产出、库存、损耗、废弃和成本证据。该方向属于未来规划，不是当前已实现能力。
